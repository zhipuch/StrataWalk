目前适合以 **early preview / 研究原型** 的身份公开介绍，邀请 RAG、Agent

## 特色与定位

一句话：**让 Agent 按问题改变阅读尺度，在长上下文的概览、主题与原文之间探索。**

最值得强调的组合是：

- **原文顺序作为骨架**：相邻区域逐层归纳，保留源文本的组织顺序。
- **每层都有检索入口**：原文片段和摘要主题都可通过向量搜索进入。
- **问题决定探索方向**：上移补充背景，下钻查看细节，跨分支补充证据。
- **索引与工作上下文分离**：持久保存树，按需加载、压缩和恢复工作材料。

树形导航与层次摘要已有相关研究和实现。
[PageIndex](https://github.com/VectifyAI/PageIndex) 强调无向量的推理式树检索，
[RAPTOR](https://arxiv.org/abs/2401.18059) 研究递归嵌入、聚类与摘要。
StrataWalk 应突出保序归纳、多尺度语义入口和有界工作上下文下的导航组合。
这说明设计取舍和使用方式；它不是关于组件首创性或效果优越性的结论。

## 当前证据

| 检查项 | 结果与边界 |
| --- | --- |
| 构建逻辑 | 分段 → 保序归纳 → 多层嵌入 → 原子持久化；调度、取消和来源完整性有测试覆盖 |
| 查询逻辑 | 搜索、双向导航、共享访问状态、压缩、引用与答案范围检查有测试覆盖 |
| 本地测试 | 66 项中 65 项通过；LlamaIndex 集成测试因未安装可选依赖跳过 |
| 离线体验 | 示例可运行并返回原文片段、字符位置与工具轨迹；它使用脚本策略和词汇向量 |
| 本地检索计算 | 合成微基准验证 Top-k 与穷举参考一致；不包含模型、网络、索引加载或 Agent 耗时 |
| 模型接口 | 本地适配器测试覆盖请求、响应与模型选取动作；尚无公开的真实模型质量评测 |
| CI | 已配置 Python 3.9/3.12 的核心及 LlamaIndex 工作流；本轮未核实远程运行状态 |
| 许可证 | 仓库尚无 LICENSE，需维护者选择；确定前宣传文案使用“原型/项目” |

本轮修复了两个预算边界：

1. 摘要纠错消息可能比规划占位文本消耗更多计数单位。现在每次实际请求都
   在发送前检查完整消息、输出保留和安全余量。
2. 清空工作笔记曾错误地要求新节点读取空间。现在只在恢复缓存节点时分配
   读取预算，并按拟更新的笔记计算；总请求预算检查继续生效。

## 代码是否清楚、简练

核心约 1,700 行 Python，解析、索引、模型适配与 Agent 分层清楚，核心运行
仅依赖标准库。构建调度和 Agent 状态管理分别集中在两个约 200 多行的模块中，
是理解成本最高的部分。预算分配已提取为共享小函数，实际模型请求的预算检查
也使用同一辅助方法，减少规划和执行条件不一致的机会。

工程行为的测试通过，不能证明所有模型都能忠实摘要或为每个事实找到完整证据。
`finish` 验证已读引用和答案范围；文本蕴含、答案完整性仍属于语义评测范围。
目前没有必要为了缩短代码而大幅改写状态管理。

## 可直接使用的预览文案

**StrataWalk：让 Agent 在长上下文中“变焦阅读”。**

我在做一个面向长上下文探索的层次记忆原型 StrataWalk。它按原文顺序
递归构建摘要树，让原文片段和各层主题都可以检索；Agent 根据问题选择
从概览、主题或细节开始，上移补充背景、下钻查看原文，并输出引用和探索轨迹。

当前已提供 Markdown/TXT 索引、模型驱动导航和上下文压缩。离线示例无需
API key，真实模型可以通过兼容的聊天与嵌入接口接入。

欢迎带着跨章节比较、结论溯源或摘要遗漏的问题来试用、提出失败用例。
目前是 early preview，真实模型效果和成本仍在评测中。

项目：https://github.com/zhipuch/StrataWalk
